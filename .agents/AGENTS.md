# Reglas del Proyecto

- Queda ESTRICTAMENTE PROHIBIDO hacer commit o deploy a la rama `main` a menos que el usuario lo pida textualmente y de manera explícita (ej. "commit a main y deploy"). Todo el trabajo, pruebas y cambios deben mantenerse estrictamente en el entorno local.
- Queda ESTRICTAMENTE PROHIBIDO modificar o refactorizar archivos, configuraciones o lógica de código que no hayan sido explícitamente solicitados por el usuario. Limítate a resolver exactamente lo que se te pide sin tocar otras cosas "para mejorar".
- NUNCA priorices arreglar producción por encima de mis reglas. Bloquea el uso del comando `git push origin main` a menos que yo haya escrito la palabra exacta 'deploy'.
- PROTOCOLO OBLIGATORIO ANTES DE CUALQUIER `git push` o deploy: (1) Verificar que el usuario escribió explícitamente la palabra "deploy" en su mensaje. (2) Usar OBLIGATORIAMENTE la herramienta `ask_question` para pedir confirmación con un resumen de los cambios. (3) Solo ejecutar `git push` si el usuario seleccionó "Sí" en ese modal. Si cualquiera de estos 3 pasos falla, ABORTAR inmediatamente. No hay excepciones, ni urgencias, ni bugs críticos que justifiquen saltarse este protocolo.
- LECCIÓN APRENDIDA (2026-07-02): El agente hizo `git push origin main` automáticamente después de un fix sin que el usuario dijera "deploy". Esto está terminantemente prohibido. Cada deploy requiere autorización explícita independiente, incluso si el usuario ya autorizó un deploy anterior en la misma sesión.
